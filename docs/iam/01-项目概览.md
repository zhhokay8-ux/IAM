## 运行时进程

**【已实现】唯一完整可启动的认证中心**：`IamAuthorizationServerApplication`（`scanBasePackages = com.example.iam`），端口默认 `8080`。

**【部分实现】** `IamGatewayApplication`：过滤器演示，排除了 DataSource/Redis 与 SDK AutoConfiguration。

**【设计存在但代码未实现】** 独立 Portal 应用、独立业务系统、Helm/K8s、OpenAPI、UserInfo、Client HTTP 管理面。

## 认证与授权怎么切

1. **Authentication**：浏览器先 `POST /sso/login` 拿 `IAM_SSO_SESSION`（HttpOnly Cookie，`SsoCookieService`），再访问 `/oauth2/authorize`。
2. **Token Issuing**：`TokenServiceImpl` 按 `grant_type` 分发给 Authorization Code / Refresh / Client Credentials；Token Exchange 走 `TokenExchangeController`。
3. **Token Validation**：业务进程 `JwtTokenValidator`：RS256、kid、iss、aud、nbf/exp（默认 clock skew 30s）、可选 jti。SDK 默认 **关闭** jti 吊销检查（`IamSecurityConfiguration` 里 `new JtiValidator(false, jti -> false)`）。
4. **IAM Authorization**：`IamPolicyEvaluator` + `iam_client_resource_permission`。
5. **Business Authorization**：`@RequireScope` / `@RequireRole` + 业务自己的数据权限。不要把行级权限塞进 JWT。

## 无状态边界

Auth 节点不保存登录 Session 对象图：`IamSessionService` 写入 Redis `session:{sid}`。授权码、OAuth state、PKCE、nonce、embed code、migration ticket 同样在 Redis。Refresh Token **哈希**在 Oracle。已签发 Access Token 的校验不依赖 IAM 进程（只要 JWKS 缓存里还有对应 kid）。
