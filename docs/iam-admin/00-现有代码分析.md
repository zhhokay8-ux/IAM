## 2. 当前 IAM 数据模型

Flyway：`iam-authorization-server/src/main/resources/db/migration`，**最新 `V15`**。历史脚本 **禁止改写**。Oracle 11g 标识符已缩短；权限表物理名为 **`iam_cli_res_perm`**（实体 `@Table(name = "iam_cli_res_perm")`）。

| 表 / 存储 | Entity | 要点 |
|---|---|---|
| `iam_client` | `IamClientEntity` | `client_id` 唯一；`client_secret_hash`（V14）；TTL 秒；`pkce_required` NUMBER(1)；状态 `ACTIVE`/`INACTIVE` |
| `iam_client_redirect_uri` | `IamClientRedirectUriEntity` | `uri_type`：`LOGIN_CALLBACK` / `LOGOUT_CALLBACK`；**无独立 back-channel 列**。BCL 实现按 `LOGOUT_CALLBACK` 查 URI |
| `iam_resource_server` | `IamResourceServerEntity` | `resource_code`、`audience` 唯一；**无 description 列** |
| `iam_scope` | `IamScopeEntity` | 绑定 `resource_id` + `scope_code` |
| `iam_cli_res_perm` | `IamClientResourcePermissionEntity` | `(client_id, resource_id, scope_id, grant_type)` 唯一；grant：`AUTHORIZATION_CODE` / `CLIENT_CREDENTIALS` / `TOKEN_EXCHANGE` |
| `iam_user` | `IamUserEntity` | `subject_id` UUID 唯一；username+tenant 唯一；email；**无 last_login_at、无 roles 列** |
| `iam_user_identity_mapping` | `IamUserIdentityMappingEntity` | V13 起唯一 `(system_code, external_user_id)`；FK `subject_id` → `iam_user.subject_id` |
| `iam_refresh_token` | `IamRefreshTokenEntity` | 只存 `token_hash`；V14 增加 `scope`/`audience` |
| `iam_signing_key` | `IamSigningKeyEntity` | 元数据 + `kms_key_id`；**私钥不在库内**（`LocalSigningKeySecretStore` 内存） |
| `iam_embed_policy` | `IamEmbedPolicyEntity` | parent/child **UUID（client 主键）**、origin、path、status |
| `iam_audit_log` | `IamAuditLogEntity` | V15 `detail`；有 `source_ip`/`user_agent` 列，**写入路径目前基本不填** |
| Redis `session:{sid}` | `IamSession` record | **无 Session 表**；无按用户枚举的一等 API（需 Redis SCAN 或补索引，不能假装有 SQL 列表） |
| Redis 其它 | — | auth code / oauth state / pkce / nonce / embed code / migration ticket / refresh status / revoked jti |

**没有的表（不要编造已存在）：** `iam_role`、`iam_admin_role`、`iam_admin_permission`、独立 Token Exchange Policy 表、系统配置表、管理员账号表。

Token Exchange「策略」= 权限行 `grant_type=TOKEN_EXCHANGE`，由 `IamPolicyEvaluator.validateTokenExchangePermission` + `TokenExchangePolicyServiceImpl` 执行。Admin 改权限即改 Exchange，**禁止再造一张平行策略表**。

## 3. 当前 Service（必须复用，禁止复制业务规则）

| 能力 | 类型 | 现有方法缺口（Admin 需要补在 Service 或 Admin 层，不要另写一套校验） |
|---|---|---|
| `IamClientService` | 接口+Impl | create / update / get / requireActive / dynamicRegister。**无 list、无 disable 专用、无 rotate secret、无独立 URI CRUD**（create 时带 URI 列表） |
| `IamResourceService` | 接口+Impl | create / update / get / requireActive。**无 list/disable 专用** |
| `IamScopeService` | 接口+Impl | create / get / requireBoundScope。**无 list/update/disable** |
| `IamPermissionService` | 接口+Impl | create / get。**无 list/revoke** |
| `IamUserService` | 接口+Impl | create / update / get / require*。update 可改 `status`。**无分页搜索、无 lock 状态机** |
| `IamIdentityMappingService` | 接口+Impl | create / list(by subject) / requireMapping。**无按系统查询、无删除/改映射** |
| `IamPolicyEvaluator` | `@Component` | 运行时校验 client/redirect/audience/scope/permission。Token Exchange 走这里 |
| `TokenExchangePolicyService` | 接口+Impl | **只有 require***，无 CRUD |
| `IamSessionService` | 接口+Impl | create / require / find / touch / revoke / expire / delete。**无 listBySubject、无全局列举** |
| `EmbedPolicyService` | 接口+Impl | **仅** `requireActive`。无 CRUD |
| `IamAuditService` | 类 | `record` / success / failure。**无查询 API**；`AuditEvent` 枚举已有 LOGIN_*、TOKEN_*、CLIENT_*、POLICY_CHANGED 等，**缺** CLIENT_DISABLED、SECRET_ROTATED、SESSION_REVOKED、USER_DISABLED 等 |
| `SigningKeyService` / `SigningKeyRotationService` | 接口+Impl | createActiveKey / getActive / getByKid / rotate / retireExpired。`KeyMetadata` **无私钥** |
| `TokenIntrospectionService` | 已有 HTTP | `POST /oauth2/introspect`，需 **confidential client** 认证 |
| `TokenRevocationService` | 已有 HTTP | `POST /oauth2/revoke`，同样需 client 认证 |
| `RefreshTokenFamilyService` / `IamRefreshTokenRepository` | 有 | 按 subject/client/session 查 hash 行。**无管理 HTTP** |

校验器已存在，必须继续用：`IamClientValidator`、`IamRedirectUriValidator`（精确 URI，禁 `*`）、`IamOriginValidator`。

## 4. 当前 HTTP（可复用 vs 不要当成 Admin）

**协议面（保持不动）：**

- `GET /.well-known/openid-configuration`、`GET /.well-known/jwks.json`
- `GET/POST /oauth2/authorize`、`POST /oauth2/token`、`POST /oauth2/token` exchange、`POST /oauth2/introspect`、`POST /oauth2/revoke`
- `POST /sso/login`、Logout、Embed、Migration

**管理面现状：**

- 仅 `/api/users/**` + 共享口令 Header
- **没有** Client/Resource/Scope/Permission REST
- **没有** `/health`、Actuator、OpenAPI/Swagger（文档与网关 permit-all 提过 health，授权服务器未实现）

成功响应：Controller **直接返回 DTO**（如 `UserResponse`、`ClientResponse`）。错误：`ApiErrorResponse`（`traceId, code, message, timestamp`），**不是** `{code:"0", data:{}}`。Admin 应 **复用错误体**；成功包装若要统一，仅用于 `/api/admin/**`，不要改 OAuth 端点。

`ClientResponse` **不含** `clientSecret` / `client_secret_hash`（正确）。`CreateClientRequest.clientSecret` 为 WRITE_ONLY；明文由调用方传入后哈希。Admin 应改为 **服务端生成并只回一次**（现 Service 未 rotate）。

## 5. 安全与认证（Admin 登录不能另起用户体系）

- 授权服务器：**无 Spring Security FilterChain 保护 `/api/**`**；安全靠自定义 Filter（TraceId、CORS 白名单、CSRF、安全头、Token 日志脱敏）。
- 用户管理：**静态共享 Token**，不是 OIDC、无角色、无细粒度 `admin.client.read`。
- SSO：`POST /sso/login` 校验 BCrypt 密码。仍无限流。
- 建议后续：Admin 作为 Client `iam-admin`（confidential + BFF 或 PKCE public 需按架构定）；权限 **新建表或 JWT claims**，仓库 **没有** `iam_role`。
- CORS：禁止 `*` + credentials。Admin Origin 必须进 `iam.cors.allowed-origins`。
- CSRF：现有 `CsrfValidationFilter` 对带 SSO Cookie 的写操作生效；Admin Session 方案必须对齐，不能关掉 Security 来过测试。

## 8. 需要新增的 API（目标前缀 `/api/admin`，Phase 1 起落地）

协议 introspect/revoke **可被 Admin 代理调用**（服务端用 Admin 自己的 confidential client，禁止浏览器直持 IAM client_secret）。

需新增（名称可按现有 REST 风格微调）：

- Dashboard、Clients CRUD + enable/disable + rotate-secret + URI
- Resources / Scopes / Permissions
- Users + identity mappings
- Sessions revoke（按 sid；按用户需先解决列举）
- Refresh tokens 元数据 + revoke
- tokens/introspect、tokens/revoke（包装现有服务）
- Embed policies CRUD
- Token exchange：对 `iam_cli_res_perm` 的 grant 筛选，**不是新表**
- Audit 查询
- Signing keys 元数据 + rotate（禁止返回私钥）
- System config：**只读映射 `application.yml` / `iam.*`**，运行时改 issuer/算法标 **READ_ONLY / RESTART_REQUIRED**，不要假动态

## 9. 需要新增的表 / 权限

**可延后、仅当 Admin RBAC 必须持久化时（建议 Phase 1）：**

- `iam_admin_role` / `iam_admin_permission` / 绑定表，**或** 用户 JWT `roles` + 硬编码权限矩阵（无独立角色表的现状）

## 11. 安全风险（Admin 必须面对，不能藏）

1. 共享 `X-IAM-Admin-Token` 无操作者身份、无审计操作人。
2. SSO 已验密码，Admin OIDC 仍依赖同一 Session；无限流/MFA。
3. 私钥仅内存，Admin Rotation 会生成新 kid；多节点/重启导致旧 JWT 验签失败。
4. Secret/Token 禁止进日志；已有 `TokenLoggingFilter`，Admin 日志必须同样脱敏。
5. 审计 `source_ip`/`user_agent` 未写入，管理追责不完整。
6. 物理删除 Client 会级联权限/URI；产品要求默认 **DISABLE**。
7. Introspect 页面存在 Token 泄露面，必须警告且不落盘。

---

## 12. 兼容性风险

Admin 与授权服务器 **同进程** 时：

- 不得改 OAuth/OIDC/SSO/Exchange/Embed/Migration/SDK/Gateway 契约
- 改 Client/Permission/Embed 必须立刻被 `IamPolicyEvaluator` / Token 发放使用（这是验收硬条件）
- `ddl-auto: validate` + Oracle 11：新表必须与 Entity 一致；Instant 已按 `TIMESTAMP` 映射
- `mvn test` / 现有 E2E（SSO、Token Exchange、Client Credentials、Embed、Migration）不得破坏
- 提示词中的 PostgreSQL 以源码为准：**当前是 Oracle**

## 13. 可复用 Controller

| 路径 | 能否当 Admin UI 直连 |
|---|---|
| `IamUserController` `/api/users` | 仅过渡；权限过粗。正式 Admin 应 `/api/admin/users` 包装同一 Service |
| Introspect / Revoke | 浏览器 **不要** 带业务 client_secret；由 Admin API 服务端调用 |
| 其它 OAuth Controller | **禁止**改成管理 CRUD |

## 14. Phase 0 结论与下一阶段

`iam-admin` 是空模块；IAM 核心可管理对象都在现有 Entity/Service 里。Admin 是 **薄 API + 权限 + 审计 + UI**，不是第二套 IAM。

**下一阶段 Phase 1：** Admin Security（`/api/admin/**` 默认拒绝、角色/权限模型、Admin Client 注册方式、替换或升级共享 Token、审计操作者）。  
未完成 Phase 1 前，不实现业务 CRUD 页面。
