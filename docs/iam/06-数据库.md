# 06 数据库

Flyway：`iam-authorization-server/src/main/resources/db/migration` V1–V15。JPA `ddl-auto: validate`。

## ER（逻辑）

```
iam_client 1—* iam_client_redirect_uri
iam_client 1—* iam_client_resource_permission *—1 iam_resource_server
iam_resource_server 1—* iam_scope
iam_client 1—* iam_refresh_token *—1 iam_user(id)
iam_user 1—* iam_user_identity_mapping（FK 到 subject_id）
iam_client 1—* iam_embed_policy（parent/child 都是 client.id）
iam_signing_key（独立）
iam_audit_log（独立）
```

SSO Session **不是**表，在 Redis。

## 表说明

### iam_client

用途：OAuth 客户端。PK `id` UUID。UK `client_id`。索引 status、owner。状态 `RegistryStatus`。写入：`IamClientServiceImpl`。读取：所有发 Token / authorize。不删除（代码无 delete API）。V14 增加 `client_secret_hash`，**不存明文 secret**。

### iam_client_redirect_uri

用途：登录回调与退出回调。`uri_type`：`LOGIN_CALLBACK` / `LOGOUT_CALLBACK`（`RedirectUriType`）。校验精确字符串匹配。Back-channel logout URI 也登记在此类型为 LOGOUT_CALLBACK。

### iam_resource_server

用途：资源服务器，字段 `audience` 即 JWT `aud`。UK resource_code、audience（V3 + 注释迁移）。

### iam_scope

用途：某 resource 下的 scope_code。绑定到 permission。

### iam_client_resource_permission

用途：client 对某 resource 的某 scope 在某 `grant_type`（`AUTHORIZATION_CODE` / `CLIENT_CREDENTIALS` / `TOKEN_EXCHANGE`）下是否允许。这是 Token Exchange 与 CC 的授权依据。

### iam_user

用途：统一用户。UK `subject_id`；UK `(tenant_id, username)`。V13 `email` 可空、**禁止当 JWT sub**（列注释）。写入：`IamUserService` / Admin API。

### iam_user_identity_mapping

用途：`system_code + external_user_id` → `subject_id`。迁移 Ticket 靠它找人。UK `(system_code, external_user_id)`。

### iam_refresh_token

用途：只存 `token_hash`（SHA-256）。有 rotation_parent_id、status、V14 `scope`/`audience`。明文 refresh 只在 Token Response 出现一次。FK subject→`iam_user.id`、client→`iam_client.id`。注意：`session_id` 列类型 UUID，而 Redis session sid 是字符串，集成时以代码写入值为准。

### iam_signing_key

用途：kid、algorithm、**kms_key_id**、status。**【已实现】不保存 RSA 私钥列**。私钥在 `LocalSigningKeySecretStore`（内存）。与“生产 KMS”设计不一致，见 99。

### iam_embed_policy

用途：parent client + child client + parent_origin + allowed_path。无 REST 写入，测试直接 `IamEmbedPolicyRepository.save`。

### iam_audit_log

用途：trace_id、event_type、subject/client/resource UUID、result、failure_reason、V15 `detail`。索引见 V11。client_id 列是 UUID，字符串 client_id 会写进 `detail`（`IamAuditService`）。

无外键级联删除业务数据的 Admin 流程。
