# 25 生产部署

**【已实现】** `Dockerfile`、`docker-compose.yml`（iam+oracle+redis）。  
**【设计存在但代码未实现】** Helm、K8s、Ingress 样例。不要伪造清单。

## 构建

```bash
export ORACLE_PASSWORD=... REDIS_PASSWORD=...
mvn -pl iam-authorization-server -am package -DskipTests
# jar: iam-authorization-server/target/iam-authorization-server-0.1.0-SNAPSHOT-exec.jar
docker compose up --build
```

镜像：`COPY ...-exec.jar app.jar`，`java -jar /app/app.jar`，暴露 8080。

## 多节点

设计上 Session 在 Redis，节点应无本地 Session。但 **签名私钥在每进程内存**：多副本各自 `createActiveKey` 会导致 kid 分裂。生产必须先替换 `SigningKeySecretStore` 为共享 KMS，或固定单签发节点。见 99。

负载均衡：sticky 非必须（Session 在 Redis）。Cookie 域指向 IAM 主机。TLS 终止后 `IAM_SSO_COOKIE_SECURE=true`，`IAM_ISSUER` 为对外 https。

密钥与 Secret：Compose 要求密码环境变量；**不要**把 private key 写进 Git。DB 只有 `kms_key_id`。

网关：可另起 `iam-gateway`，但无转发规则，通常前面仍用 Nginx。JWKS 缓存在每个业务节点 1h。
